The CPU vLLM wheel was 0.28.0, Omni source reported 0.29.0rc2, and the installed PyTorch CPU build was 2.13.0. Qwen used the installed vLLM 0.29.0 CUDA wheel, WSL kernel `6.18.33.2-microsoft-standard-WSL2`, RTX 5090 Laptop (24,463 MiB), driver 610.71, BF16 compute, eager mode, 2 GiB explicit host offload, one sequence and 512-token context. All values are single-run observations; they are not medians.

The code changes make vLLM-native `qwen3_5` a one-stage Omni pipeline, project explicit `language_model_only` and `cpu_offload_gb` to the owning stage, skip vLLM's `-1` unmapped-slot sentinel in both prefix-cache write paths, and accept both vLLM 0.28 three-field and 0.29 four-field min-token state. The image probe first refused a 1,024-token context because the available 0.14 GiB KV cache was below the 0.38 GiB requirement. The successful run explicitly used a 512-token context and 0.85 GPU memory utilization. No context or precision was changed silently.

The missing primary MiniCPM-o 4.5 and InternVLA-A1 checkpoints are now fully downloaded at pinned revisions. Every safetensors file was SHA-256 checked against the corresponding Hugging Face metadata: [MiniCPM-o](evidence/weights/minicpmo.json), [InternVLA base](evidence/weights/internvla_base.json), and [InternVLA Place_Markpen fine-tune](evidence/weights/internvla_place_markpen.json). The required InternVLA Cosmos encoder/decoder and Qwen3-VL processor files were downloaded separately. Existing Spark-X2.5 4B and 1.7B INT8, Qwen3-TTS, Qwen3.8 FP8 and Qwen3.8 NVFP4 artifacts covered those model families. Optional official Spark 1.7B BF16 and Qwen3.8-27B BF16 transfers remain paused; they are additional artifact variants, not replacements for the present family weights. InternVLA source checkpoints carry a CC BY-NC-SA 4.0 license; the current download is for local research validation.

The pinned MiniCPM-o checkpoint (`openbmb/MiniCPM-o-4_5`, `503e754207c94da6bb26850b4469f367c9ea3582`) has four weight shards totaling 18.74 GB (decimal). InternVLA base (`InternRobotics/InternVLA-A1-3B`, `08cf716d413aa8208a34f346cd8824e6ff901205`) and Place_Markpen fine-tune (`Jia-Zeng/InternVLA-A1-3B-FineTuned-Place_Markpen`, `0a557c6a503e6545b369bff2f34c76a410bbd190`) each have a 6.72 GB weight file. Checkpoint integrity is a prerequisite, not pipeline qualification.

InternVLA's real-weight synthetic probe uses [probe_internvla_actions.py](../../probe_internvla_actions.py) and the public `DiffusionRequestBatch` boundary with `strict_load=True`. The raw [JSON](evidence/internvla/internvla_finetune_synthetic.json) and [log](evidence/internvla/internvla_finetune_synthetic.log) record a 36.394 s startup, 1.222 s synchronized forward and 6,683,068,416 bytes of PyTorch CUDA peak allocation during the measured forward. This uses Transformers 5.14.1, vLLM 0.29.0, PyTorch 2.13.0+cu130 and BF16 policy weights on WSL/RTX 5090 Laptop (driver 610.71). Output actions are float32. The inputs are synthetic zeros, so neither task behavior nor action semantics are established.

MiniCPM-o used the actual three-stage Omni pipeline, real checkpoint and [constrained deploy profile](evidence/minicpmo/minicpmo_24gb_offline.yaml) on the same WSL/RTX 5090 Laptop, with vLLM 0.29.0, Transformers 5.14.1, BF16, eager execution and `VLLM_USE_FLASHINFER_SAMPLER=0` (no CUDA toolkit is present for FlashInfer JIT). The profile limits model length, multimodal inputs and concurrency, and explicitly offloads 5 GiB of thinker weights to host RAM; it does not qualify the stock full-capacity profile. The [raw log](evidence/minicpmo/mini_fixed_e2e.log), [text and token IDs](evidence/minicpmo/0_2c17288b-c543-4aaa-9a6a-e661ab14c97b.txt) and [WAV](evidence/minicpmo/output_0_2c17288b-c543-4aaa-9a6a-e661ab14c97b.wav) record 182.47 s engine startup and 20.53 s for the single measured prompt. The WAV has 124,800 mono PCM16 samples at 24 kHz (5.2 s), 124,579 nonzero samples, peak absolute amplitude 18,852 and RMS 3,430.39. There is no ASR or listening check, so matching speech content is unverified.

The earlier [three-stage run](evidence/minicpmo/mini_template.log) and [text-only run](evidence/minicpmo/mini_text_only.log) each emitted repeated punctuation. A [one-stage thinker probe](../../probe_minicpmo_thinker.py) isolated zero logits during real request prefill: the Omni runner passed MiniCPM-o its allocated embedding buffer before populating it, and MiniCPM-o treated that buffer as precomputed input. The runner now marks only actually populated embeddings; MiniCPM-o computes token embeddings otherwise. The [repaired thinker log](evidence/minicpmo/mini_thinker_fixed.log) and the three-stage result above show coherent text. The default profile's cache-admission failure and intermediate YAML/import/parameter failures remain in the other `evidence/minicpmo/mini_*.log` files; the fixed result does not erase those constraints.

The other rows still need actual local devices, a matching complete backend/artifact, memory admission, and model-specific quality and profiling. In particular, no ADB device is attached, native Windows CPU attention operations are missing from the installed extension, AMD iGPU/NPU routes lack a verified stateful whole-model deployment, and there is no qualified joint CPU+iGPU+NPU execution plan. AI Hub component results remain component evidence.

For interrupted transfers, [download_pending_weights.py](../../download_pending_weights.py) resumes each pinned repository and verifies the SHA-256 of every safetensors file against Hugging Face metadata. Its local logs live under `models/.weight_download_status/` outside Git; the verified manifests are copied into `evidence/weights/`. A status of `verified` means only that the weights are complete; it does not qualify any inference path.
