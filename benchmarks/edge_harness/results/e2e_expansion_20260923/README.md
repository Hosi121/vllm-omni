Both runs used Ryzen AI 9 HX 370 on Ubuntu 26.04/WSL2 kernel `6.18.33.2-microsoft-standard-WSL2`, with 30.91 GiB WSL RAM and 8 GiB swap. The CPU environment has Python 3.12.13, PyTorch 2.13.0+cpu (`torch.cuda.is_available() == False`), vLLM 0.28.0 and Transformers 5.14.1; Omni source is 0.29.0rc2. MiniCPM-o used BF16, eager execution, serial requests, `OMP_NUM_THREADS=8`, 1 GiB CPU KV cache **per stage**, 2,048-token thinker / 512-token talker limits, text input only, and no CPU weight offload. Its full three-stage run used swap, so the timing applies only to this constrained machine and workload. The output [text](evidence/minicpmo/0_28854dbf-b6b7-4f1d-a35a-52f254ab9d9e.txt), [WAV](evidence/minicpmo/output_0_28854dbf-b6b7-4f1d-a35a-52f254ab9d9e.wav), [raw log](evidence/minicpmo/minicpmo_cpu_full_compat4.log), [deployment config](evidence/minicpmo/minicpmo_cpu_offline.yaml) and [artifact check](evidence/minicpmo/minicpmo_cpu_artifact_report.json) are retained. The WAV has 124,800 PCM16 frames, 124,147 nonzero samples, peak absolute amplitude 21,850 and RMS 3,319.41; no listening or ASR check was performed. An earlier [one-stage CPU thinker run](evidence/minicpmo/minicpmo_cpu_text.log) also produced coherent text in 8.67 s after 36.02 s startup, but that diagnostic topology is not the speech pipeline.

The separate [20-request profile](evidence/minicpmo/minicpmo_cpu_profile_20.json) records every measured output and sampled memory; the [JSONL](evidence/minicpmo/minicpmo_cpu_profile_20.jsonl) survives interruption, and the [run log](evidence/minicpmo/minicpmo_cpu_profile_20.log) retains worker details. One warmup was excluded. All 20 measured requests returned the same thinker token sequence, nonzero 124,800-sample audio, and request wall times 20.95–23.33 s; nearest-rank p50/p95 were 21.86/22.97 s (real-time factor 4.20/4.42 for 5.2 s of audio). Sampled WSL available RAM reached a minimum of 3.80 GB and swap use a maximum of 5.75 GB; summed process-tree RSS reached 29.04 GB but double-counts shared pages. These are 0.5 s samples during requests, not load-peak or unique-resident-memory measurements. Audio and text were returned together at request completion, so the profile cannot establish playable-stream latency, and no concurrency or 30-minute thermal run was performed.

The MiniCPM-o CPU environment initially failed in the talker because vLLM 0.28 calls the multimodal processor with a prompt and three-value return contract, while 0.29 expects a `BatchFeature`. The 0.28 MiniCPMV processor also lacks `_call_hf_processor_on_prompts`. The local processor now handles both APIs. The next run failed before vocoder inference because `stepaudio2-minicpmo` was absent from the isolated CPU venv; installing version 0.1.1 with its dependencies enabled the final run. [All failed logs](evidence/minicpmo/) remain available; no failure was relabeled as a pass.
