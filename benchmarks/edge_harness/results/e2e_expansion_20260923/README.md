This extends the [60-cell device × model matrix](../e2e_profiling_20260922/evidence/summary/README.md) with previously unrun WSL CPU and native Windows paths. The September 22 timing tables remain historical. MiniCPM-o now has a separate 20-request serial text-to-speech timing run; each InternVLA timing remains one observation. None is a sustained or full-modality profile. The [checkpoint manifests](../e2e_recovery_20260923/README.md) pin the real weights. No model, precision or context was silently substituted.

Both runs used Ryzen AI 9 HX 370 on Ubuntu 26.04/WSL2 kernel `6.18.33.2-microsoft-standard-WSL2`, with 30.91 GiB WSL RAM and 8 GiB swap. The CPU environment has Python 3.12.13, PyTorch 2.13.0+cpu (`torch.cuda.is_available() == False`), vLLM 0.28.0 and Transformers 5.14.1; Omni source is 0.29.0rc2. MiniCPM-o used BF16, eager execution, serial requests, `OMP_NUM_THREADS=8`, 1 GiB CPU KV cache **per stage**, 2,048-token thinker / 512-token talker limits, text input only, and no CPU weight offload. Its full three-stage run used swap, so the timing applies only to this constrained machine and workload. The output [text](evidence/minicpmo/0_28854dbf-b6b7-4f1d-a35a-52f254ab9d9e.txt), [WAV](evidence/minicpmo/output_0_28854dbf-b6b7-4f1d-a35a-52f254ab9d9e.wav), [raw log](evidence/minicpmo/minicpmo_cpu_full_compat4.log), [deployment config](evidence/minicpmo/minicpmo_cpu_offline.yaml) and [artifact check](evidence/minicpmo/minicpmo_cpu_artifact_report.json) are retained. The WAV has 124,800 PCM16 frames, 124,147 nonzero samples, peak absolute amplitude 21,850 and RMS 3,319.41; no listening or ASR check was performed. An earlier [one-stage CPU thinker run](evidence/minicpmo/minicpmo_cpu_text.log) also produced coherent text in 8.67 s after 36.02 s startup, but that diagnostic topology is not the speech pipeline.

The separate [20-request profile](evidence/minicpmo/minicpmo_cpu_profile_20.json) records every measured output and sampled memory; the [JSONL](evidence/minicpmo/minicpmo_cpu_profile_20.jsonl) survives interruption, and the [run log](evidence/minicpmo/minicpmo_cpu_profile_20.log) retains worker details. One warmup was excluded. All 20 measured requests returned the same thinker token sequence, nonzero 124,800-sample audio, and request wall times 20.95–23.33 s; nearest-rank p50/p95 were 21.86/22.97 s (real-time factor 4.20/4.42 for 5.2 s of audio). Sampled WSL available RAM reached a minimum of 3.80 GB and swap use a maximum of 5.75 GB; summed process-tree RSS reached 29.04 GB but double-counts shared pages. These are 0.5 s samples during requests, not load-peak or unique-resident-memory measurements. Audio and text were returned together at request completion, so the profile cannot establish playable-stream latency, and no concurrency or 30-minute thermal run was performed.

The CPU-only InternVLA run used the same BF16 policy checkpoint, synthetic six-camera history/state input and zero diffusion noise as the CUDA reference. The raw [CPU JSON](evidence/internvla/internvla_pure_cpu_synthetic.json), [CPU log](evidence/internvla/internvla_pure_cpu_synthetic.log), [CPU actions](evidence/internvla/internvla_pure_cpu_actions.npy), [CUDA JSON](evidence/internvla/internvla_cuda_synthetic_with_actions.json), [CUDA actions](evidence/internvla/internvla_cuda_actions.npy) and [numerical comparison](evidence/internvla/internvla_pure_cpu_cuda_parity.json) are retained. The CUDA reference used the WSL RTX 5090 Laptop and PyTorch 2.13.0+cu130; its one forward took 1.33 s. The action difference has maximum absolute error 0.00993 and mean absolute error 0.00117. No reference-task tolerance is available, so this comparison is evidence of numerical proximity, not an accuracy pass.

The native Windows runs used Windows 11 build 26200, NVIDIA driver 610.71 for the GPU path, Python 3.12.10, PyTorch 2.13.0+cu130, vLLM 0.29.0, Transformers 5.14.1, and the current Omni source. The CPU run explicitly selected the CPU policy despite the CUDA-capable wheel. The placement-checked reruns assert that all policy parameters and the output action tensor remain on the requested device. Both loaded the same checkpoint from the local WSL filesystem through a UNC path; Windows CPU and GPU runs used the same synthetic input and zero diffusion noise as the WSL reference. The native [CPU JSON](evidence/internvla/internvla_windows_cpu_synthetic.json), [GPU JSON](evidence/internvla/internvla_windows_gpu_synthetic.json), [CPU log](evidence/internvla/internvla_windows_cpu_synthetic.log), [GPU log](evidence/internvla/internvla_windows_gpu_synthetic.log), [CPU actions](evidence/internvla/internvla_windows_cpu_actions.npy), [GPU actions](evidence/internvla/internvla_windows_gpu_actions.npy), [CPU/WSL comparison](evidence/internvla/internvla_windows_cpu_wsl_cpu_parity.json), and [GPU/WSL comparison](evidence/internvla/internvla_windows_gpu_wsl_cuda_parity.json) are retained. Native vLLM import initially failed on a Linux-specific CuMem allocator patch; the added Windows guard resolved the import. Native default GBK source decoding also required `PYTHONUTF8=1`. Both platform differences are setup requirements, not model-quality evidence. Power mode and thermal state were not captured.

The MiniCPM-o CPU environment initially failed in the talker because vLLM 0.28 calls the multimodal processor with a prompt and three-value return contract, while 0.29 expects a `BatchFeature`. The 0.28 MiniCPMV processor also lacks `_call_hf_processor_on_prompts`. The local processor now handles both APIs. The next run failed before vocoder inference because `stepaudio2-minicpmo` was absent from the isolated CPU venv; installing version 0.1.1 with its dependencies enabled the final run. [All failed logs](evidence/minicpmo/) remain available; no failure was relabeled as a pass.

Reproduce from the repository root with the verified local checkpoint paths:

```bash
export PYTHONPATH="$PWD" OMP_NUM_THREADS=8 MKL_NUM_THREADS=8 TOKENIZERS_PARALLELISM=false
export CUDA_VISIBLE_DEVICES= VLLM_TARGET_DEVICE=cpu VLLM_CPU_KVCACHE_SPACE=1 VLLM_ENABLE_V1_MULTIPROCESSING=0
/home/zhout/project/edge_infer/.venvs/omni-cpu/bin/python examples/offline_inference/minicpmo/end2end.py \
  --model /home/zhout/project/edge_infer/models/MiniCPM-o-4_5 \
  --deploy-config benchmarks/edge_harness/results/e2e_expansion_20260923/evidence/minicpmo/minicpmo_cpu_offline.yaml \
  --query-type text --modalities text,audio --num-prompts 1 --output-dir /tmp/minicpmo-cpu

/home/zhout/project/edge_infer/.venvs/omni-cpu/bin/python benchmarks/edge_harness/probe_internvla_actions.py \
  --model-dir /home/zhout/project/edge_infer/models/InternVLA-A1-3B-FT-Place_Markpen \
  --cosmos-dir /home/zhout/project/edge_infer/models/Cosmos-Tokenizer-CI8x8 \
  --processor-dir /home/zhout/project/edge_infer/models/Qwen3-VL-2B-Instruct-processor \
  --device cpu --output /tmp/internvla-cpu.json --actions-output /tmp/internvla-cpu-actions.npy

/home/zhout/project/edge_infer/.venvs/omni-cpu/bin/python benchmarks/edge_harness/profile_minicpmo_text_speech.py \
  --model /home/zhout/project/edge_infer/models/MiniCPM-o-4_5 \
  --deploy-config benchmarks/edge_harness/results/e2e_expansion_20260923/evidence/minicpmo/minicpmo_cpu_offline.yaml \
  --warmups 1 --repeats 20 --output /tmp/minicpmo-cpu-profile-20.json
```

For native Windows InternVLA, set `PYTHONUTF8=1`, put this checkout on `PYTHONPATH`, and run `benchmarks/edge_harness/probe_internvla_actions.py` with the same model/processor paths as above but Windows-accessible UNC paths; use `--device cpu` or `--device cuda` and separate output paths.
