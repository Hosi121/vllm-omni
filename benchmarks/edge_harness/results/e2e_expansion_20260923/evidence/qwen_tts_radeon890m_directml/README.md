# Radeon 890M DirectML Qwen3-TTS attempted route

This is a **failed whole-model quality route**, not a Radeon Qwen3-TTS pass. It used the official [Qwen3-TTS 0.6B CustomVoice checkpoint](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice/tree/85e237c12c027371202489a0ec509ded67b5e4b5) and `qwen-tts==0.1.1` on Windows 11 build 26200. The isolated runtime had PyTorch 2.4.1+cpu, `torch-directml==0.2.5.dev240914`, Transformers 4.57.3, torchaudio 2.4.1, and AMD Radeon 890M driver `32.0.22018.6001`. `torch_directml.device_name(1)` identified Radeon 890M; all model parameters were checked on `privateuseone:1` after the move. The RTX 5090 Laptop was enumerated as device 0 but was not selected.

The [probe](../../../../experiments/probe_qwen_tts_directml.py) loads the real talker and speech tokenizer, explicitly moves the model to DirectML, and records the selected adapter, model placement, precision and failure phase. The wrapper caches `self.device` at construction; setting it to the chosen DirectML device after the model move corrected the first CPU-input/GPU-weight mismatch. The following attempts retain the next genuine boundaries:

| Attempt | Result | Raw record |
|---|---|---|
| FP16, original sampling | Reached talker token sampling, then failed at DirectML `torch.gather`. | [report](qwen_tts_dml_890m_20260923.json), [log](qwen_tts_dml_890m_20260923.log) |
| FP16, repetition penalty 1.0 | Bypassed gather, then failed at a DirectML `torch.cat` of an empty int64 prefix and one next token. A minimal `(1,0) ⊕ (1,1)` int64 DirectML reproduction failed the same way. | [report](qwen_tts_dml_890m_rp1_20260923.json), [trace](qwen_tts_dml_890m_rp1_trace_20260923.log) |

It is **not a quality pass**. | [report](qwen_tts_dml_890m_greedy_20260923.json), [WAV](qwen_tts_dml_890m_greedy_20260923.wav), [log](qwen_tts_dml_890m_greedy_20260923.log), [ASR proxy](qwen_tts_dml_890m_greedy_asr_20260923.json) |

The tested dtype/sampling changes and workaround are explicit; none is silently substituted for the accepted CPU BF16 path. These results constrain this DirectML runtime/configuration, not every possible Radeon graph or quantized artifact. The [separate Q8_0 GGUF Vulkan experiment](../qwen_tts_radeon890m_joint/README.md) found a scoped CPU+Radeon route with two intelligible named outputs. It does not repair DirectML or establish that the whole model runs on Radeon alone.
