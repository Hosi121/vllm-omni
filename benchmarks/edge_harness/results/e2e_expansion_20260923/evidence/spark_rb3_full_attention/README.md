# Spark-X2.5 attention layer on Dragonwing RB3 Gen 2 / QCS6490

**The hosted RB3 kit (QC Linux 1.6, Hexagon v68) ran one real Spark-X2.5-1.7B attention layer on CPU with near-FP32 numerical parity. A separate W8A8 NPU variant executed but has 20.9% hidden-state relative L2 error on the pinned fixture. Neither variant qualifies full Spark generation.** The [S24 provenance](../spark_s24_full_attention/README.md) pins the FP32 source ONNX, its W8A16 QDQ form, calibration and exact 1,024-token-cache input. The [artifact manifest](artifact_manifest.json) pins downloaded compile outputs outside Git.

Four routes were tested on exact device **Dragonwing RB3 Gen 2 Vision Kit**, using AI Hub Workbench client 0.55.0 and service build in each raw job report:

| Route | Jobs and outcome | One-layer evidence |
|---|---|---|
| Reuse S24-built W8A16 QNN DLC `mq9y70k0n` | [Inference](inference_report.json) `j57e4k4lp` and [profile](profile_report.json) `jp4y1m1vp` both failed: `QnnModel_composeGraphsFromDlc: MODEL_GRAPH_ERROR`. | No outputs or timing samples. |
| Compile same QDQ source for RB3 as W8A16 QNN DLC `mn0g3ye8m` | [Compile](compile_rb3_report.json) `jgnznozrg` passed. Targeted [inference](targeted/inference_report.json) `jglyxoy85` and [profile](targeted/profile_report.json) `j5687r80g` both failed with the same graph error. | Device-specific recompilation did not resolve this graph/runtime failure. It does not establish that all W8A16 Spark exports are unsupported. |
| Compile original FP32 source to ONNX `mmxj02ljq`, request CPU | [Compile](compile_cpu_report.json) `jglyxowj5`, [inference](cpu/inference_report.json) `jgolrodqg` and [profile](cpu/profile_report.json) `jpvldemk5` passed. [Audit](w8a8/audit_report.json): 100 samples, p50/p95 5.610/5.761 ms (minimum 5.089 ms). This precision is **numerically unqualified**; no next-token/task tolerance is established. |

All successful jobs used the same fixture dataset `d7m83gjy2` and returned finite FP32 hidden/new-key/new-value tensors. The service `estimated_inference_time` equals each sample minimum, not the median. The [CPU](cpu/audit_report.json) and [W8A8 NPU](w8a8/audit_report.json) audits pin source and fixture hashes, exact job/device/model IDs, output hashes, placement rows and full precision differences. [Submission records](compile_w8a8_submission.json), [initial failed submissions](inference_submission.json), [RB3 W8A16 compile submission](compile_rb3_submission.json), and [CPU compile submission](compile_cpu_submission.json) preserve attempted settings. The scripts [collect existing jobs](../../../../experiments/collect_spark_aihub_component.py) and [audit fallback variants](../../../../experiments/audit_spark_qualcomm_fallback.py) without embedded credentials.

The CPU and NPU numbers are different precisions and outputs, not a qualified speedup comparison. Neither job includes 27 other decoder layers, prefill, continuous decode, KV/ring, sampling, a resident Omni controller, complete-request timing or sustained power/thermal behavior. Workbench is a test facility, not a deployment dependency.

**Matrix status: CPU component numerical pass; W8A8 NPU component execution with unresolved numerical quality; NOT E2E.** The next NPU experiment needs representative multi-prompt calibration and layer/next-token parity gates, then a compatible full-model artifact. The full embedded route also needs device-local state, memory admission, cancellation and sustained profiling. The two W8A16 graph errors remain specific to the tested QDQ export and SDK/device combination.
