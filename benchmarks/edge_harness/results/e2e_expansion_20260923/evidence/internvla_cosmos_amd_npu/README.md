# InternVLA Cosmos encoder export and HX370 AMD NPU candidates

**A real encoder ONNX export passed CPU numerical checks; no tested artifact executed on the AMD NPU.** The source is the pinned InternVLA-A1 Place_Markpen Cosmos CI8x8 encoder checkpoint, SHA256 `520a3b878e72ee872faccb1211b5d622d194c0fdd177f2f6df097586b8fa98e5`. The unchanged Omni source module was exported at fixed FP32 `[6,3,256,256]` input to `[6,16,32,32]` latent using PyTorch 2.13.0+cpu, opset 21, ONNX IR 10. The [export report](export_report.json) pins the model/source hashes, ONNX graph SHA256 `fee79864e393df35475ba243e14b4995c5651aa33e7e182cd1fda726425668b7`, 124.65 MB external-data SHA256 `b9bc3411c10f05daec2ff977698ee100979ef756ed7f0d685275403517558b58`, fixture hash and package versions. The large graph/weights and fixtures remain outside Git under `/home/zhout/project/edge_infer/models/InternVLA-cosmos-onnx/`; copies used for Windows probing are under `C:\Users\zhout\w2\internvla_cosmos_npu\`. They are not deployable from this checkout alone.

Two deterministic fixed-shape fixtures (a ramp and a patterned patch) compared ONNX Runtime CPU output with the real source module. Relative L2 differences were **8.74e-7** and **2.29e-6**, respectively. This proves the FP32 graph preserves these two encoder outputs on CPU; it does not prove action quality, real-image quality or NPU execution. The [export log](export.log) and [`export_internvla_cosmos_onnx.py`](../../../../experiments/export_internvla_cosmos_onnx.py) reproduce this boundary.

The [A16W8 QDQ sweep](quant_sweep.json) used QUInt16 activations, QInt8 weights and MinMax calibration on those two fixtures. Quantizing Conv+MatMul per tensor changed the full encoder output by **11.77%/5.03% relative L2** (ramp/pattern); the [native Windows CPU gate](conv_matmul_cpu_report.json) now rejects that artifact before NPU compilation. Per-channel Conv+MatMul improved the error to **3.14%/2.77%**, still above the explicit 0.1% component gate. MatMul-only QDQ left Conv on FP32 CPU and retained source-level CPU parity (**9.46e-7/2.34e-6**; [native CPU report](matmul_cpu_report.json)); that is a different, much smaller candidate, not a qualified NPU route. ONNX Runtime preprocessing with symbolic inference failed on this export's Constant handling; skipping symbolic inference produced a valid graph but did not improve the candidate's numerical results ([preprocessing sweep](preprocessed_quant_sweep.json)).

The original full Conv+MatMul artifact reached VitisAI session compilation but emitted a native **`Attrs doesn't contain attribute scale`** fatal assertion; its process remained in the crash path and was interrupted after several minutes ([readable log](probe.log), [unaltered log](probe.log.raw.bin)). MatMul-only A16W8 and the preprocessed MatMul-only version each exited with a native LLVM **`SmallVector` index assertion** during compilation ([logs](matmul_probe.log), [preprocessed log](preprocessed_matmul_probe.log), with unaltered `.raw.bin` copies). The [attempt record](compiler_attempts.json) pins candidate hashes, numerical results and process outcomes. None produced a live inference session or profiler node attribution. These failures constrain these exact A16W8 graph layouts and VitisAI EP 1.8.63.0 on the Ryzen AI 9 HX 370; they do **not** prove the model or NPU inherently unsupported. The host was Windows 11 build 26200 with AMD NPU driver 32.0.203.329, ONNX Runtime 1.30.0 and ONNX 1.22.0. The previous [Spark output-head NPU component](../spark_amd_npu_output_head/README.md) remains a separate proven placement case.

The next viable experiment is to produce a model-aware, VitisAI-supported **whole encoder or coarse substage** artifact with a representative calibration set, then pass CPU numerical and policy-action tolerances before measuring NPU node placement, same-device handoff, full-policy latency and shared-RAM admission. A small MatMul partition inside this encoder would not by itself establish an end-to-end benefit. The matrix therefore remains **NOT E2E** for InternVLA on AMD NPU.

Reproduce the CPU export from this checkout:

```bash
ROOT=/home/zhout/project/edge_infer
EVIDENCE=benchmarks/edge_harness/results/e2e_expansion_20260923/evidence/internvla_cosmos_amd_npu
"$ROOT/.venvs/omni-cpu/bin/python" benchmarks/edge_harness/experiments/export_internvla_cosmos_onnx.py \
  --encoder "$ROOT/models/Cosmos-Tokenizer-CI8x8/encoder.safetensors" \
  --output "$ROOT/models/InternVLA-cosmos-onnx/cosmos_encoder.onnx" \
  --fixtures "$ROOT/models/InternVLA-cosmos-onnx/fixtures.npz" \
  --report "$EVIDENCE/export_report.json"
```

The Windows [`probe_internvla_cosmos_amd_npu.py`](../../../../experiments/probe_internvla_cosmos_amd_npu.py) validates copied artifact hashes, runs the CPU numerical gate first, then registers the installed VitisAI EP and requires actual NPU node events. Use `--cpu-only` to stop after numerical validation; use `--prequantized --candidate-sha256` to pin a prepared layout. Native compiler assertions may terminate the process before it can write a JSON report, so the raw logs and candidate hashes above are the authoritative failure record.
