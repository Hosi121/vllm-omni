# Native Windows CPU MiniCPM-o: spoken visual question

The pinned GGUF [native CPU backend](../minicpmo_cpp_windows_cpu/README.md) completed the same synthetic red-square image and spoken “What color is the square in the image?” request as the [Radeon 890M hybrid](../minicpmo_cpp_radeon890m_prompted/README.md). Pinned Whisper tiny.en independently transcribed the spoken input with WER 0 in the Radeon record. The [raw CPU log](full.combined.log) shows zero GPU layers, CPU vision and CPU Token2Wav/vocoder, actual index-1 image/audio prefill, and the response **“The square in the image is red.”** All eight logged language token IDs matched the Radeon run on the identical checkpoint and inputs; see the [cross-device check](../minicpmo_cpp_radeon890m_prompted/cpu_radeon_parity.json).

The [bounded verifier](../../../../experiments/verify_minicpm_cpp_output.py) checked the ten weight hashes, exact executable/input hashes, completion marker, text, and three contiguous nonzero mono 24 kHz [WAV chunks](round_000/tts_wav/). It assembled their unchanged PCM into a [2.32 s WAV](full_merged.wav); the [report](full_report.json) includes each hash. Local pinned [Whisper tiny.en](output_asr.json) transcribed the speech as the exact answer, WER 0 as an intelligibility proxy. The CPU and Radeon PCM hashes differ, so waveform parity is not claimed.

One cold CPU process took 24.66 s. [100 ms sampling](full.profile.json) observed 13.11 GB maximum RSS and 13.31 GB maximum private bytes; these are not guaranteed loading peaks or a repeated profile. The one prompted image case is stronger than the earlier unprompted tone fixture but does not qualify general visual/audio understanding, playable streaming, Omni admission/state/cancellation or sustained operation. The Windows GGUF backend remains standalone outside Omni.
