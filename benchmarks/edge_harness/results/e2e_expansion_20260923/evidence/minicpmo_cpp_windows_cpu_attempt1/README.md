# Native Windows MiniCPM-o C++ CPU attempt 1 — incomplete audio

The pinned `openbmb/MiniCPM-o-4_5-gguf` ten-file set and the `tc-mb/llama.cpp-omni` CLI cross-built for native Windows CPU loaded and processed index 1 containing a synthetic JPEG red square and 2 s/440 Hz audio. Text was generated, but the full speech path **failed its completion check**. The CLI exited with status 0 after 615.19 s even though only 15 contiguous `wav_N.wav` chunks existed and `generation_done.flag` was absent. The raw [stdout](full.stdout.log), [stderr](full.stderr.log), [process profile](full.profile.json), and [partial WAV chunks](tts_wav/) are preserved. Sampled process RSS/private-byte maxima were 9.74/9.95 GB at 100 ms intervals; these are not guaranteed loading peaks.

The C++ CLI waited at most 120 s for the audio completion marker, then stopped its worker threads without turning the missing marker into a nonzero exit. Its optional merger also searched for `tts_output_chunk_N.wav`, while the vocoder wrote `wav_N.wav`. Both defects are visible in the raw logs. The follow-up CLI patch makes the wait bound configurable and returns status 2 on timeout; the retry uses a separate x86-64-v3 build and work directory. No result from this attempt is classified as a complete native Windows path.
